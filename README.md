## Image identity: the registry digest

The VIO image is built once by `.github/workflows/publish-image.yml`, pushed to GHCR, and
pinned as one line in **`docker/IMAGE_REF`** (`ghcr.io/<owner>/vioreg-openvins@sha256:...`).
`scripts/run_sequence.sh`, `python -m vioreg.score` and the nightly workflow all use that
ref by default. `IMAGE=<repo>@sha256:...` overrides it, and the override must be digest-pinned too.

    docker pull "$(cat docker/IMAGE_REF)"      # needed once before running or scoring locally

The recorded `image_digest` is the registry digest of that ref, confirmed by
`docker image inspect` RepoDigests. The runner refuses to start, and the scorer records
`null` (an invalid result), when the local image does not carry exactly the pinned
digest. Each run writes `run<k>.image_digest`, and a mismatch fails the result.

Why not the image ID of a local build (what was recorded before S5b):
- **It changes on every rebuild.** `apt-get update` makes builds non-reproducible, so
  every rebuild has a new ID and would need a new baseline.
- **It depends on Docker's storage mode.** The containerd image store reports the
  manifest(-list) digest as `.Id`. The classic overlay2 store reports the config digest.
  The same image built on a laptop and on a CI runner can carry different IDs.

The registry digest names the same bytes on every host, every pull and every store.
Changing the image means a new publish, a new `docker/IMAGE_REF` and a deliberate
re-baseline (docs/ci.md).

## Result JSON contract (`results/<seq>.json`, written by `python -m vioreg.score`)

The key set is frozen (enforced by `tests/test_score.py`):

    sequence, backend, vio_commit, image_digest, harness_commit, config_hash, runs,
    align, skip_s, ate{ok, rmse, median, max, coverage, n}, rpe{ok, rmse, delta_s},
    per_run_ate_rmse, wall_s

- `vio_commit`: the OpenVINS commit baked into the image (label `vioreg.ov_ref`).
- `image_digest`: the **registry digest** of the pinned image (`sha256:...`), see below.
- `harness_commit`: git HEAD of this repo, with `-dirty` appended if `src/`, `configs/`
  or `scripts/` has uncommitted changes (untracked files included).
- `config_hash`: sha1 over `estimator_config.yaml` plus the kalibr IMU and IMU-camera
  yamls it references (`relative_config_imu`, `relative_config_imucam`), with the file
  contents concatenated in sorted file-name order. The configs are baked into the image at
  `/ws/src/open_vins/config/<config>/`; a run that mounts an override directory must be
  scored with `--config-dir` pointing at it. `scripts/run_sequence.sh` writes a
  `run<k>.config_hash` sidecar per run, and any mismatch fails the result.
  (Before S3, this hashed only `estimator_config.yaml`.)
- `ate` and `rpe` come from the median run by ATE RMSE (the upper median for an even run
  count). Any failed run makes `ok=false`, and the exit code is non-zero.
