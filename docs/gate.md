# Gate v2: what fails, what warns, and why the margins are what they are (session S4)

**Result: RPE separates the measured legitimate variants from the known-bad ones; ATE does
not.** Under gate v2 every fine-outcome legitimate variant passes and every known-bad
variant fails. The separating margin is the **per-sequence RPE ratio, 1.28**: the
legitimate maximum is 1.145 and the known-bad minimum is 1.431, leaving ×1.118 room on
each side. The **ATE geometric mean** gives no usable margin: the worst fine legitimate
variant scores 1.286 and the mildest known-bad one 1.306. Its margin of 1.5 is a
**backstop only**. Two "innocent" changes made MH_03_medium genuinely fail (a 4,437 km
divergence, and a late initialization at half coverage); the gate fails them, which is
correct, because it judges outcomes, not intent.

- Thresholds: `configs/thresholds.yaml` (format v2, generated by `scripts/make_thresholds.py`)
- Logic: `src/vioreg/gate.py`; CI tier `tests/test_sequences.py`; tests `tests/test_gate*.py`
- Data: `docs/sensitivity/sensitivity_s4.json` (every run of every variant on 3 sequences)
- Image `sha256:f08eacb1…`, OpenVINS `93adc241`, baseline config `5adca0e7`;
  host AMD EPYC 7763 (`docs/sensitivity/host_codespace.json`)

## Why the old rule could not work

`threshold_from_baseline()` returns `max(median + 3·MAD, median × 1.15, 0.01)`. Serial
OpenVINS is bit-deterministic (S3), so MAD = 0 and the noise term grants zero tolerance.
Only the arbitrary +15% remains, and S3b showed innocent changes moving one sequence's ATE
by up to +73%. The helper is kept, with a note that v2 does not use it.

## The design (as specified, with one flagged deviation)

1. **Hard fail per sequence:**
   - a missing (when `HARNESS_REQUIRE_RESULTS=1`) or unparsable result
   - missing provenance
   - `ate.ok` or `rpe.ok` false, or any failed run
   - coverage below baseline − 0.01
   - associated pose count `ate.n` below baseline − **4** (see the deviation below)
2. **RPE RMSE per sequence, as a ratio to baseline**: fail above `rpe_ratio_max` = **1.28**.
3. **ATE RMSE only as the geometric mean** of per-sequence ratios over **all** baseline
   sequences: fail above `ate_geomean_ratio_max` = **1.5**. There is no single-sequence ATE
   gate. A missing or unusable sequence makes the aggregate fail.
4. **Same `vio_commit`, `image_digest` and `config_hash`**: every `run*.tum` is compared
   pose by pose with `baselines/<seq>.tum` (`pose_equivalent`). A difference is a
   **warning**: a `::warning` annotation in Actions, stderr elsewhere. If no trajectories
   exist (the CI golden tier), it is a note.
5. **Baselines are keyed** by (sequence, vio_commit, image_digest, config_hash). No matching
   entry fails with **"needs re-baseline"**. Several entries per sequence are allowed.

**Deviation, flagged for the owner: `pose_count_drop_max: 4`.** The spec said "pose
count below baseline". But the recorder (ov_eval `pose_to_file`, a separate ROS node; the
`poseimu` publisher queue is 2, `ROS1Visualizer.cpp:48`) can lose up to 2 poses at the
**start** of a run (seen on MH_03 in S4) and the final pose at the **end** (seen in S3b).
In both cases the poses it did record were bit-identical to the other runs. A strict rule
would fail identical re-runs on recorder races. The allowance of 4 (2 at each end) covers
exactly those, and `pose_equivalent` now tolerates the same edges.

**Consequence of rule 5:** any real `OV_REF` bump or config edit, even an innocent one,
fails with "needs re-baseline". So the RPE and ATE margins only ever judge results whose
key matches: the same VIO, image and config on a different host, harness version or
environment. That is the open S5 question. S3b showed the system is chaotic enough that
such drift could move ATE as much as an innocent parameter change, so the measured
parameter variants below are the best available proxy for how far an innocent
perturbation moves the metrics.

### Separation and the chosen margins

| Signal | Legitimate, fine outcome (max) | Known-bad (min) | Separates? | Margin | Room |
|---|---|---|---|---|---|
| RPE ratio, per sequence | **1.145** (MH_03 start −2 s); 1.094 among 3-sequence variants | **1.431** (`num_pts 50`, MH_01) | **yes** | **1.28** (geometric midpoint) | ×1.118 above legit, ×1.118 below bad |
| ATE geometric mean, 3 sequences | **1.286** (`fast_threshold 18`) | **1.306** (`num_pts 50`) | **no** (1.6% apart) | 1.5, a backstop only | ×1.17 above legit; catches 2 of 3 bad (2.04, 3.97) |
| Hard checks (coverage, pose count, ok) | never moved (except recorder races) | **never moved** | no | n/a | n/a |

Outcome with these margins:

| Case | RPE ≤ 1.28 | ATE geomean ≤ 1.5 | Gate |
|---|---|---|---|
| 5 fine legitimate variants + baseline (3 sequences) | ✓ | ✓ | **pass** |
| fine legitimate start −2 s (MH_01, MH_03) | ✓ | n/a | **pass** (RPE) |
| `bad_num_pts_50` | ✗ 1.431 (MH_01) | ✓ 1.306 | **fail** (RPE only) |
| `bad_gravity_mag_9.0` | ✗ 1.524 | ✗ 2.038 | **fail** |
| `bad_imu_noise_discrete` | ✗ 3.092 | ✗ 3.967 | **fail** |
| legit-but-broken `fast_threshold_22` (MH_03 diverged) | ✗ 4241.7 | ✗ 33.9 | **fail** (correctly) |
| legit-but-broken start +2 s (MH_03 late initialization) | ✗ 10.1 | ✗ 2.16 | **fail** (also coverage 0.477) |

**What this means:**
- **RPE does the real work.** No known-bad variant moved coverage, pose count or `ok`,
  and the ATE mean misses `num_pts 50`.
- **The hard checks did not catch the MH_03 divergence** (`fast_threshold 22`, ATE
  4,437 km, coverage unchanged at 0.979). Only the ratios did. "Coverage unchanged" does
  not mean "filter healthy".
- **The room is thin.** ×1.118 on each side rests on one known-bad variant
  (`num_pts 50`) and one legitimate one (MH_03 start −2 s). A new innocent change could
  exceed 1.28, or a new bug could stay below it.

### What the margins rest on (not a bound)

| Set | Variants | Runs | Independent samples |
|---|---|---|---|
| Legitimate, 3 sequences (signal table) | 7 + baseline | 72 + baseline | 1 per variant × sequence (deterministic) |
| Legitimate, single-sequence extras (start −2 s, V1 +1 s) | 3 | 9 | 1 each |
| Known-bad | 3 | 27 | 1 per variant × sequence |
| Of which run in S4 | MH_03 legit (9) + all known-bad | 54 | n/a |

Serial replay is deterministic, so 3 runs per cell are 1 sample, not 3. These are **the
observed extremes of a small, one-at-a-time sample, not a bound**: 5 knobs, 2 values
each, 3 sequences, 3 known-bad variants, one host.

## Tests

Tests (`tests/test_gate.py` 32, `tests/test_gate_goldens.py` 7,
`tests/test_thresholds.py` 15, `tests/test_sequences.py` CI tier):
- **A typical baseline run passes.** `tests/golden_results/<seq>.json` are the real S3
  baseline score JSONs; the gate passes them, and the aggregate ratio is exactly 1.0.
- **A legitimate variant passes.** `tests/golden_results/variants/legit_fast_threshold_18.json`
  is the worst fine-outcome legitimate variant: real results on 3 sequences, re-keyed to
  the baseline key.
- **A known-bad variant fails.** `known_bad_num_pts_50.json` is the hardest to catch; it
  fails on RPE (MH_01 1.431).
- **Missing results fail closed** with `HARNESS_REQUIRE_RESULTS=1` (and so does the
  aggregate).
- **A missing baseline key fails** with "needs re-baseline" (e.g. a changed `config_hash`).
- **The committed margins sit inside the measured gaps.** A guard test pins `rpe_ratio_max`
  strictly between 1.145 and 1.431, against silent loosening.
- Pose warning: a positive control (same key, MH_01 trajectory swapped for another
  variant's) **passes with a warning**. Real S3 results with trajectories pass with no
  warning.

**The gate was broken on purpose twice, and the tests caught it both times:**

| Mutant | Tests that failed |
|---|---|
| RPE ratio check disabled (`if False and ratio > …`) | `test_rpe_ratio_over_margin_fails_with_numbers`, `test_known_bad_variant_fails_on_rpe` |
| Baseline key ignores `config_hash` | `test_missing_baseline_key_fails_with_needs_rebaseline`, `test_each_key_field_must_match[config_hash]`, `test_missing_baseline_key_fails_needs_rebaseline` |

## Not known yet

- **Cross-machine behaviour (S5):** whether the CI runner reproduces the baseline under the
  same key. If it does not, every CI run gets a pose warning, and the margins decide.
- Whether 1.28 holds up against more legitimate changes, other sequences (MH_02, V1_02…),
  or regressions that act like `num_pts 50` but milder.
- Per-sequence RPE has an asymmetric failure mode: a regression that hurts only global
  consistency (slow drift) could pass RPE and stay under the ATE backstop.
